# Pinned to exact versions (not >=) so `pip install -r requirements.txt` gives
# every machine running this app the same Playwright/Chromium build and the
# same library versions — unpinned ranges let two machines' venvs drift apart
# over time (installed on different days), which was silently changing PDF
# text metrics and print timing between machines. See requirements-lock.txt
# for the full transitive dependency set (fastapi/pandas/etc.'s own deps)
# pinned the same way, generated via `pip freeze`.
#
# IMPORTANT — pinning `playwright` here only pins the *Python package*, not
# the Chromium *binary* it drives. `pip install` never re-downloads that
# binary; only `playwright install` does. A machine whose browser cache
# predates this pin (or was populated by an earlier one) keeps using its old
# Chromium build forever, invisibly — `pip freeze` still reports the correct
# pinned playwright version either way. Confirmed root cause (2026-09-19) of
# two machines on the identical commit, with identical `pip freeze` output,
# still rendering the trend section's pagination differently. After ANY
# `pip install -r requirements.txt` on a machine that already had a
# venv/browser cache, also run `python -m playwright install --force
# chromium` — see pdf.py's `_get_persistent_browser`, which now logs the
# actual running Chromium version/path on launch so this doesn't have to be
# discovered by diffing two PDFs again.
#
# To upgrade deliberately: bump a version here, `pip install -r
# requirements.txt` in the venv, then regenerate the lock with
# `pip freeze > requirements-lock.txt` and commit both — and re-run
# `playwright install chromium` if the playwright version itself changed.
